Image-error fallback

Doc 26 §5's own named state. When image fails to load, the component falls back to initials, then the icon form — never a broken-image glyph. The image URLs below are deliberately unreachable to trigger the native <img> (error) event live.

States

Per SPEC.md §3 — presentational and non-interactive, same precedent as ino-tag/ino-meter-group: no hover/active/ focus-visible/disabled/readonly/invalid/ loading states apply. Only default and the image-error fallback above are carried.

Mobile — React Native + Flutter ports

Per doc 26 §5 "Port both" — InoAvatar ships for React Native (mobile/react-native/src/components/InoAvatar.tsx) and Flutter (mobile/flutter/lib/widgets/ino_avatar.dart) with the same content-form priority, five-step size scale, and decorative/informative accessibility contract as web. Mobile is always fluid — no density split to reconcile.
