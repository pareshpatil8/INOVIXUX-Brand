Variants/Structure — plain container, collapsible, footer slot

Most panels are static grouping (collapsible="false", the default) — plain header text with no interactive affordance. Setting collapsible renders the whole header bar as a disclosure button (aria-expanded + aria-controls). The [ino-panel-footer] slot renders an optional actions bar, same idiom as [ino-card-footer].

States

disabled dims the whole panel and native-disables the toggle. readonly only locks the collapse toggle (behavior-only, no corresponding ARIA attribute — region doesn't support readonly any more than group does, SPEC.md §2); content stays fully interactive. loading dims the body and shows a spinner (aria-busy) while the header/footer stay visible. invalid/ empty are not carried — a panel has no value of its own to validate (SPEC.md §2).

Labels — header wrapping, RTL, landmark

header is the component's one label — aria-labelledby wires it to the role="region" host so assistive tech announces the panel as a named landmark (SPEC.md §3). The stylesheet uses logical properties only (padding-inline, border-block-end/-start), so it mirrors correctly under dir="rtl".

Keyboard contract

When collapsible, the header is a native <button>: Tab reaches it as a normal stop (readonly instances stay reachable too — only a disabled panel's toggle leaves the tab order, via native disabled); Space or Enter toggles collapsed and emits collapsedChange (native button activation, no custom keydown handling). When not collapsible, the header has no tab stop at all.
