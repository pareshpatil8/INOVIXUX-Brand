Sizing — gutter tokens (no sm/default/lg scale)

Per the spec row, there is no per-instance size axis. The gutter's interactive hit width reads --ino-target-min (24px, the existing WCAG 2.2 SC 2.5.8 token) and its visible line reads --ino-border-width-hairline (1px, the same token ino-divider already uses) — both reused rather than new primitives, since tokens.css is frozen after Wave 0 (SPEC.md, header note).

Labels — n/a

Per the spec row, this component has no label of its own: a splitter divides layout, it doesn't name a value. Each collapse toggle still carries its own dynamic aria-label ("Collapse panel before gutter" / "Expand panel before gutter", etc.) — see the collapse-handle example above.

Keyboard contract

Each gutter is role="separator", always in the tab order (a splitter has no single "current" gutter the way a tablist has a current tab). On a focused gutter: ArrowLeft/ArrowRight (horizontal) or ArrowUp/ArrowDown (vertical) resize by resizeStep (default 5%); Home collapses the panel before the gutter to its minSize; End pushes the panel after it down to its own minSize. RTL flips the horizontal Arrow-key mapping to match the visual direction (SPEC.md §4). Collapse toggles are plain <button>s — Tab/Enter/ Space, no custom handling needed.
