Paste — validateOnPaste

Copy 12a34 and paste it into any field above. With validateOnPaste on (the default) the disallowed characters are stripped and 1234 is inserted at the caret; with it off the whole paste is refused and the value is left untouched. Either way inoKeyfilterReject fires exactly once, with the full clipboard text rather than a single character.

Two forms, one implementation

The row above uses the element form. The field below uses the attribute form, [inoKeyfilter], on an <ino-input> you already own — the preferred shape when you render the field yourself, since it adds no wrapper node. Both are the same directive: <ino-keyfilter> applies it through hostDirectives, which is why the Props and Events tables below list the directive's surface.

Density — the host field's axis, not this component's

A key filter contributes no colour, spacing, radius, elevation or type, so it has no density register of its own — its host is display: contents, which keeps it out of layout entirely. What density changes is the field it guards. Both panes run the same num filter; only the row height differs.

States, sizing and labels — n/a (directive)

Recorded, not omitted (doc 26 §2 point 6). This is a behaviour-only primitive: it paints nothing, so it has no hover / focus-visible / active / disabled / readonly / invalid / loading state of its own, no size scale, and no label API. Every one of those belongs to the field it's attached to, and <ino-input> demonstrates its own full set on its own page. A disabled input here would only duplicate the host field's — which already stops keydown firing before this directive sees it. Same disposition [inoFocusTrap] records, for the same reason.

Keyboard, IME and assistive technology

Filtering happens only on keydown, and only for a single printable character with no modifier held. Tab, Backspace, Delete, arrows, Home/End, Enter and every Ctrl/Cmd/Alt combination — copy, paste, undo, select-all, screen-reader command keys — are never intercepted. Composition is never touched either: the handler returns immediately while isComposing is true, so non-Latin text typed through an IME is never tested against these (Latin/numeric) presets and never retroactively stripped.
