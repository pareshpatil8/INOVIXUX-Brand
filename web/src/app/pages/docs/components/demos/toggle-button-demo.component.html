Variants — the two faces

The component owns its visible label and swaps onLabel/offLabel (and onIcon/offIcon when provided) as pressed flips — it takes no projected content, so the two faces can never drift out of sync with the state. Click any button: the caption under it reads pressed back live, and the face changes from the bordered ino-button secondary shape to the accent-filled primary shape.

States

The standard state set. disabled dims to 50% and leaves the tab order; readonly stays focusable and fully legible but silently ignores the press, exposed as aria-disabled (not aria-readonly, which a native button role drops — SPEC.md §5); loading is aria-busy plus natively disabled, with the current face still on screen next to the spinner. The three locked instances below are shown in both faces, since each face has its own colour pair to check. Hover and :focus-visible are live on every enabled instance — tab onto one for the focus ring.

Sizing — sm / default / lg

size is typed InoControlSize, a type alias — the manifest extractor records "values": null for that row, which is why the generated props table shows no enumerated values and the generic renderer produced no size row. The three rungs read the full five-alias --ino-control-* set (height, roomy inline padding, font size, icon size, gap) — the same set ino-button reads. Both faces are shown at every rung.

Note the heights these rungs resolve to here: this page runs in the dense register, so they are 28 / 32 / 40px, not the 32 / 44 / 52px of the fluid register. The component's documented size="default" = 44px (--ino-target-comfortable) is the fluid figure — see the fluid pane in the next section, which does measure 44px. The contract's floor is that size="default" never drops below 32px even in dense mode, which is exactly what the middle rung does here.

Density — dense vs. fluid

Density is a global [data-density] token axis, not a per-component @Input(). This docs page renders in the dense register ([data-density="dense"] on the layout host); the right-hand pane overrides to fluid. The component's base rule reads the bare unsuffixed --ino-control-* aliases and the size classes only re-point them, so density composes with size for free rather than needing its own rules.

Labels — accessible name, wrapping, RTL

A toggle button is self-labelling from its own text content, so ariaLabel is only written to the DOM when the visible label is empty (the icon-only case in the first row above) — a duplicate accessible name on a labelled button could only drift from the visible one. There is no required or hint-text input: a toggle button is rarely a "required field" in the form sense, and error covers the one case that matters. The stylesheet uses logical properties only (border-inline-start-color, padding-inline), including the spinner's gap notch, so both faces mirror correctly under dir="rtl".

Dense-table usage

A row-level flag inside a dense table — the narrowest realistic placement, and the two faces stay distinguishable at table scale without a separate "compact" visual language. These stay at size="default" rather than dropping to sm on purpose: in the dense register default resolves to exactly the 32px floor the accessibility contract promises, while sm would land at 28px — under the minimum target. Reach for size="sm" in a fluid-register layout (where it is 32px), not to squeeze an already-dense table.

Keyboard contract

Native <button> activation, nothing custom: Tab focuses (and reaches the readonly instances too — only disabled/loading leave the tab order); Space or Enter toggles, flipping aria-pressed and emitting pressedChange. No arrow-key handling: this is a single independent button, not a radio-style group — for a mutually exclusive set, reach for <ino-select-button> instead.
