Two forms, one implementation

The directive form, [inoAutofocus], attaches to a field you already own — the preferred shape, no wrapper node. The element form, <ino-autofocus>, wraps projected content and finds the first focusable element inside it for you. Reload this page (or revisit it) and focus lands on the directive-form field below; both forms run the identical resolveTarget() lookup, so there is nothing to compare beyond which element ends up focused first in document order.

The element form above is mounted with [inoAutofocus]="false" so opening this page doesn't fight the directive-form field for initial focus — two autofocus targets on one page is exactly the ambiguity this directive exists to avoid within a single container, not something to demonstrate twice at once.

Route change — inoAutofocusTrigger

Angular's Router never moves focus on navigation, and a reused component instance (same route, new params) never re-runs ngOnInit — so neither gives this directive a second activation for free. Bind inoAutofocusTrigger to a value that changes on every navigation worth re-focusing for (a NavigationEnd id, in real use); "Simulate navigation" below stands in for that. Tab away from the field, then click it.

Explicit target — inoAutofocusTarget

Without a target, the directive focuses the host if it's focusable, else the host's first focusable descendant. inoAutofocusTarget overrides that lookup with a CSS selector resolved within the host — useful when the first field in document order is not the one that should receive focus (a prefilled field ahead of the one the user still needs to complete).

Interplay with [inoFocusTrap]

SPEC.md §3: inside an ancestor [inoFocusTrap], this directive is a no-op — unconditionally, even while the trap is disabled. The trap's own inoFocusTrapInitialFocus owns initial placement instead. Toggle the trap below and tab away, then toggle it back: with the trap present, the field below is not re-focused on toggle, because [inoAutofocus] defers to the trap the moment it finds one as an ancestor.

States, sizing and labels — n/a (directive)

Recorded, not omitted (doc 26 §2 row 6; see SPEC.md §2). This is a behaviour-only primitive: it paints nothing, so it has no hover / focus-visible / active / disabled / readonly / invalid / loading state of its own, no size scale, and no label API — every one of those belongs to whatever element ends up focused, exactly as [inoFocusTrap] and [inoKeyfilter] record for the same reason. The one real, binary state is inoAutofocus itself (on/off), demonstrated throughout this page via [inoAutofocus]="false" on the element-form example above.
