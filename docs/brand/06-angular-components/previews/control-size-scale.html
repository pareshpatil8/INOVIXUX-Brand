Control-size scale — sm / default / lg

The values behind every component's size @Input (tokens.css §12, INO-124). Size and density are two axes, not one: density is container-scoped and describes a screen, size is per-instance and describes one control on that screen. A size="sm" button is small relative to its neighbours in either density — it is not a fixed pixel count. Full contract: control-size-scale.md.

--ino-control-height-default is pinned to --ino-row-min-height in dense (both 32px), so adding a button to a table row does not make the row taller than its neighbours. check-theme-parity.mjs asserts that equality.

One track cannot serve both halves of the library: a field's value must align under its label, so it takes the tighter padding; a label-bearing pressable needs air, so it takes -roomy. Both are logical (padding-inline), so RTL is free.
